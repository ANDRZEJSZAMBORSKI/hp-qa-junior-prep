### O tym rozdziale

**N3** opisuje, jak **podzielić kolekcję pytest na sensowne zestawy** i dobierać zakres uruchomienia według **ryzyka**, **obszaru zmian** i **kosztu** (czas, infrastruktura, flaki). Markery w `pyproject.toml` to główny mechanizm; workflow GitHub Actions i CMD Dockera definiują **domyślną politykę CI**.

Powiązane rozdziały: [Markery pytest](#markery-pytest), [GitHub Actions](#github-actions), [M1](#m1--równoległe-uruchamianie-i-izolacja-zasobów), [M2](#m2--zdalna-przeglądarka-selenium-grid-i-ui-w-dockerze), [N1](#n1--raporty-allure), [N2](#n2--jira-i-testrail), [J3](#j3--mock-device-inventory-api-chmura-i-dfu), [O](#o--niezawodność-automation-retry-flaky-ci-gates-ai).

### Po co testy oparte na ryzyku

**Risk-based testing** to nie „mniej testów dla oszczędności”, lecz **świadomy wybór**: co ma paść w pierwszej kolejności, gdy psuje się build, konfiguracja, kontrakt API, UI lub integracja z MockServer. W tym repozytorium:

- **Smoke** — minimalny sygnał, że szkielet frameworka żyje (settings, abstrakcje, część UI smoke).
- **Regression wąska** — markery `api`, `mocks`, `distributed_lab`, `config`, … zgodnie ze zmienionym kodem.
- **Domyślne CI** — szybki przebieg bez przeglądarki i bez Compose na runnerze bez `mock-api`.
- **Pełna kolekcja** — wszystkie wykryte testy (lokalnie, nightly, przed release, CMD Dockera).

Jeden test może mieć **wiele markerów**; `--collect-only` liczy przynależność do markera — sumy kolumn **nie** dają liczby unikalnych testów.

### Inwentaryzacja: `--collect-only`

Poniższe polecenia **zbierają** node id testów i **nie uruchamiają** ich. Liczby w tabeli dotyczą bieżącego drzewa repozytorium (**476** testów w `tests/`). Po dodaniu testów przelicz:

```bash
python -m pytest --collect-only -q
python -m pytest --collect-only -q -m smoke
```

### Smoke vs regresja vs pełny suite

| Podejście | Rola | W projekcie |
|-----------|------|-------------|
| **Smoke** | Szybki sygnał po zmianie | `-m smoke` (17 testów) |
| **Regresja wąska** | Obszar dotknięty diffem | `-m api`, `-m mocks_httpx`, `-m distributed_lab`, … |
| **Regresja CI (szeroka)** | Stabilna brama bez UI/Dockera | **391** testów, filtr **tests** |
| **Pełny suite** | Cała kolekcja | wszystkie **476**, plus UI/selenium/compose w razie potrzeby |

**Severity** i **feature** w Allure (N1) oraz priorytet case w TestRail (N2) uzupełniają markery.

### Rekomendowana polityka uruchomień

| Zdarzenie | Zestaw | Przykład | Ryzyko |
|-----------|--------|----------|--------|
| Lokalnie po zmianie | Według obszaru | `pytest tests/mocks_lab -m mocks_httpx -q` | Zepsuty mock HTTP / ApiClient |
| Szybka brama | Smoke | `pytest -m smoke -q` | „Czy framework żyje?” |
| Push / PR (jak CI) | CI-391 | `pytest -m "not ui and not selenium and not compose" -q -n auto` | API/L2/L3/mocki/device_lab bez Grid |
| Po zmianach UI | Podzbiór Playwright | `pytest -m "ui and not serial" -q` | Scenariusze przeglądarki |
| Nightly / przed release | Pełny + infra | `pytest -q`; `docker compose up … tests`; profile M2 | Compose, Grid, pełna kolekcja |

Granice CI są w `.github/workflows/tests.yml`.

### Uruchomienie (nie tylko collect)

```bash
pytest -m smoke -q
pytest -m "not ui and not selenium and not compose" -q -n auto
pytest -m compose -q
pytest tests/distributed_lab -m distributed_lab -q
pytest tests/parallel_lab -m parallel_lab -n 2 -q
```
